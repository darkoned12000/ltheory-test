## 3. libphx code review (pruned — only meaningful findings)

Verified-passing today: `GLSL 116 OK` (`tools/validate_glsl.py`), `configure.py test` (all suites + UI integration PASS).

### 3.1 Rendering pipeline (Draw/RenderState/RenderTarget/RenderJobQueue)
- Flat immediate batch (`Draw.cpp`): VBO-based, batch key = (GL mode, RGB, alpha); `Imm_Draw` chunks into `DRAW_MAX_VERTS` (4096).
- Widget batch (`Draw_WidgetRect`): SDF rects with per-rect attributes; merges same-(shader, blend) runs.
- `Mesh_Draw`/`LodMesh_Draw` steady state ≈ 14 GL calls/object (2 bindBuffer + 3 enableAttrib + 3 attribPointer + draw + 3 disable + 3 bindBuffer).
- Stale ⚠️: `Draw_Push` drops vertices when the static scratch overflows; only reachable by direct callers — the batch commits before overflow, so low risk.
- `RenderTarget` push/pop, `Viewport` push/pop, `ClipRect` — all hook `Draw_FlushPending()`.
- `RenderJobQueue`: SDL thread pool for rigid-body matrix extraction; mutex+condvar, generation-based wakeup; workers touch no GL/Lua/allocator; clean shutdown. Cap 8 workers.

### 3.2 Shader system
- `#autovar` lines stripped in preprocess; real `uniform`s declared in shader files upload at `Shader_Start` (eager — the documented "autovar trap": start the shader inside the RT viewport push).
- Graceful runtime failure: fallback to last-good shader + in-game overlay (`Renderer.lua` overlay).
- Global VAO (required by core profile); one VAO for process lifetime.
- Notable convention: pass uniforms via `glUniform*` (uploads from Lua via FFI `Shader.SetFloat/SetFloat2/SetFloat3/SetInt/SetMatrix`), textures via texture-unit counter + `glActiveTexture`.

### 3.3 Font system
- Shelf-packed atlas, per-font, gamma 1.8. Glyph nodes are now freed (leak fixed). `FONT_ATLAS_MAX = 8192` (was 4096 — deferreditems branch).

### 3.4 Audio (miniaudio)
- Engine mixer forced stereo, 40 ms periods + 100 ms gain smoothing (prevents crackle/zipper).
- Per-frame `setPitch` throttled in ThrustController (resampler crackle prevention).
- `Sound_EnsureLoaded` uses `Fatal` on missing files — intentional (broken install). 3D tuning measured (AGENTS): inverse rolloff, minDist 10 / rolloff 2 → ~36% gain at 12 units; `Sound_Set3DMinMaxDistance` per-sound fix available via FFI.

### 3.5 Textures
- stb_image v2.30 (verified byte-identical to upstream). Magenta fallback for missing images. Anisotropic filtering applied per-texture via `Cache.Texture(filtered=true)`; no global aniso default.
- TexCube IR map generation for env lighting.

### 3.6 Resource system
- `Resource_LoadBytes`/`LoadCstr` call `Fatal` on missing — intentional (missing required resources = broken install). Dev vs. distributable path resolution.

### 3.7 Engine init
- SDL3 migration complete; GL 4.6 core; GLEW 2.3.1. One global VAO for process lifetime.

### 3.8 Input
- SDL3 input mapping; gamepad hotplug; axis Y-inversion; focus-loss releases buttons. No axis deadzone — micro-drift possible, tuning only.

### 3.9 Scene graph / Components (Game layer)
- Entity component system (addHealth, addInventory, addSockets, addRigidBody, addVisibleMesh, ...); Event.Destroyed for damage/death. EconomyRegistry (registry-based economy scan — removed 1.06 ms/frame system-wide cost).

### 3.10 Scene graph — Entity death
- Health 0 → Event.Destroyed → Explodable burst; `System:sweepDestroyed()` removes dead children.

### 3.11 Unused / dead code (defer signals)
- HmGui + ImGui coexist (consolidation optional; ImGui test-only).
- ALSA/WINMM MIDI — unused, harmless.
- VR support (VR.cpp, Socket.cpp, etc.) was REMOVED (deleted from the tree; see commit history — "Removed unused shaders, added new billboard math test, moved completed tasks to docs" + `reviewphx` branch history).

### 3.12 Gen pipeline (SDF.cpp, Mesh_FromSDF.cpp, etc.)
- CPU SDF volume generation → marching-cubes meshes; planet/asteroid/nebula; intermediates freed after gen. Peak ~5-10 MB per SDF at 64³. One-time cost per sector, acceptable.

## 5. Performance measurements (PerfProbe, 4K, RX 7900 XTX, Mesa 26.3.1)

Baseline scene (nebula, sun shadows, full post chain, debug panel, ~10,663 entities, 4,272 streamed chunks, ~8,400 rocks):

```
mean  ≈ 8.83 ms/frame  → ~113 fps
update  = 2.08 ms   (physics + entity Lua)
stream  = 0.24 ms   (asteroid-field streaming)
drawRecord = 6.60 ms   (CPU-side draw recording)
p95 ≈ 10 ms
```

→ **the frame is ~85% CPU-side**; GPU idle-ish. This matches the user's 80–110 fps band.

The batcher (`PERF_VARIANT=batched`) measures *slower* on this scene (`update=3.09 ms`, `drawRecord=7.08 ms` → ~92 fps) — off by default for a reason; on this scene the legacy path is fine.

## 6. Direction advice

### GPU-bound or CPU-bound?
- CPU-bound (evidence): drawRecord 6.6 ms, update 2.1 ms.
- GPU: unproven — `PHX_PROFILER=1` prints per-scope CPU breakdown; PerfProbe A/Bs (no-post, no-bloom, sparse-field) find the GPU bill.

### If you want more FPS now (evidence-based)
1. **Draw record (6.6 ms)** — the flat batch + LodMesh path. Options: enable/tune the batcher (measured slower on this scene — try it; if it wins on other scenes, enable), or micro-optimize `Draw.cpp` scratch upload/flush.
2. **EconomyRegistry** — already fixed a 1.06 ms/frame scan; remaining scan could be inlined into the registry (cheaper than re-scan).
3. **Per-frame Lua dispatch** — `System:render` broadcasts to the entity tree and each `Entity:renderVisibleMesh` runs `material:start/stop` + `mesh:draw()`. Profile with `PHX_PROFILER=1`; if the self-term cost dominates, follow-up work is batching at the entity level (the batcher infra exists).

### If you want more graphics fidelity
- Everything GPU-side is modern (HDR/tonemap, GTAO, CSM+sun shadows, IBL) — extend OpenGL; Vulkan is the wrong tool now (see §8).

## 8. The Vulkan question (from the feasibility analysis, file-cited)

- The engine is **already on the latest OpenGL** (4.6 + GLSL 460 — the modern floor). No urgent reason to migrate to Vulkan.
- The engine's draw model is **CPU-bound, not GPU-bound** — Vulkan would do nothing about the draw-record costs the user sees in PerfProbe.
- There is **no GPU abstraction today**: ~84 direct `gl*` callsites (Draw 799, Mesh 493, Shader 530, RenderTarget 181, OpenGL 79, Window 101, Tex2D 337, Font 461, HmGui 430, GPUBuffer 65...). A Vulkan port is a renderer rewrite, not a swap.
- **Best path if Vulkan is wanted later:** measure GPU time first (`PHX_PROFILER=1`); only migrate if a pass is materially GPU-bound. Hedge: build the GPU abstraction boundary first (~3–6 months at experienced-dev pace), then swap the backend.
- Estimated full port: **~6–12 months, ±2×** — high sync/memory-model debugging risk. Easy mappings: draw paths, GPUBuffer/SSBOs (already Vulkan-shaped), compute, textures, blending/cull/depth/scissor. Hard bits: y-flip (silent corruption), `glPolygonMode` (no core Vulkan equivalent), readbacks, G-buffer/lighting/post-chain passes, every draw-path command recording.
