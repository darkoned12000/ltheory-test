# Limit Theory — Roadmap

The GL/GLSL 4.6 core ladder, the FMOD→miniaudio audio swap, and the library-currency pass are **complete**. The engine is fully 64-bit and runs the deferred+post rendering path on a modern core profile. What's left is feature investment, not correctness. Ordered roughly by expected impact / dependency order; each item is a self-contained project.

## Completed
- **Multithreaded render/submit (#10)** — done 2026-09-04 (see `multithreading.md`): pre-flight + Phases 0, 1, 3, 4, 5 complete (CPU batching, worker-built batches, persistent pooling; equivalence proven per phase via image-diff, flag-gated off by default). Committed validators: `phx_validate_drawbatch` (grouping, 9 cases) + `phx_validate_renderqueue` (threading barrier/order/shutdown, real bodies headless) via `configure.py test`; `DrawJob` ABI guarded by C++ `static_assert` + Lua `ffi.sizeof` assert; `Config.render.workers` override (0=auto). Deferred sub-phases (not deleted):
    - *GL instancing (Phase 2):* per-instance attributes + shader variants; no payoff while `(shader,mesh)` groups stay ~size 1 — re-add keyed by seed/canonical mesh once #7 unifies asteroid meshes.
    - *Pool reuse for Gen/particles (Phase 6):* no measured benefit (particles already GPU-compute; Gen is Lua-only spawn-time code workers can't execute); revisit only if profiling shows these as limiters *and* after resolving the Lua/worker boundary.
    - *Optional Phase 7* (GPU indirect draws) explicitly later/small; low priority.

## Rendering & graphics
1. **HDR + tonemapping — implemented but NOT yet visually verified** (blocked on the DebugWindow refactor, see "Known polish / tech debt" below): the lit buffer (RGBA16F throughout the deferred+post chain) now runs a true HDR pipeline. Bloom is a Karis-weighted mip pyramid (`filter/bloompre` soft-knee prefilter → `bloomdown` → `bloomup` scatter chain on `dsBuffer0/1`, levels steered by `postfx.bloom.radius`), composited **additively pre-tonemap** in `bloomcomposite`. Then `filter/tonemap` applies exposure (`2^EV`, `postfx.exposure.ev`, default 0) + a selectable operator (`postfx.tonemap.operator`: AgX default, plus ACES fitted, Filmic Hable, Khronos PBR Neutral) and encodes sRGB with ordered dither in the same pass. Operators live in `res/shader/include/tonemapping.glsl` (AgX taken from three.js/Filament, verified gray-neutral + monotone numerically). Landed with it on branch `add-hdr`: film grain (`filter/grain.glsl`, `postfx.grain.*`), re-wired vignette, aberration, radialblur, and a global texture-filter quality knob (`render.textureFilter`; `Cache.filterMode` + `Material.applyFilterMode`). `Config.gpu` (script/Config.App.lua) is now the commented source of truth for the whole picture surface and seeds every Setting at startup, including the previously-unwired `superSample`. Offline-validated (121/121 shaders) + equivalence-gated headless (same-seed A/B dump shows raw linear output is screen-black, expected for this scene's light levels). **STATUS: committed 2026-09-05 but not yet tuned/manually tested in-game — the DebugWindow that presents these knobs needs a refactor before the visual pass can happen.**

## Vastness & atmosphere systems
13. **Procedural streaming + LOD crossfade for endless sectors (atmosphere / vastness)** — the single biggest lever for the "never-ending, you are alone in a vast expanse" feeling. Render distance is what sells it: to feel endless you must keep generating/streaming content ahead of the ship and cull behind it, with no seam or pop-in. Design:
    - **Streaming/culling:** generate + stream new sectors/asteroid fields/nebulae into an expanding radius around the player (frustum + distance cull), recycle/despawn what falls behind — so the world reads as continuous rather than a fixed arena. The existing SDF `Gen/` pipeline + compute particles are reusable generators; extend them to be spawn-on-enter / kill-on-exit.
    - **LOD crossfade:** no hard LOD pop-in. Each entity renders at progressively lower-detail LODs and *crossfades* between them (alpha/scale blend) so detail degrades smoothly as it recedes — the eye never notices a discrete switch, which is what sells "forever." Asteroids are ideal: `max(15, scale*10)` health + cascading children already spawn at multiple scales.
    - **Fog + tonemapping:** distance fog / density-based fade ties distant geometry into the atmosphere; pairs with roadmap #1 (HDR/tonemap). The horizon should dissolve rather than snap to a hard edge — this is where "loneliness" and scale land.
    - **Feeling targets (acceptance criteria):** no pop-in or seam across long flights; asteroid/nebula density stays roughly constant as you move (feels endless); the horizon fades into atmospheric haze, not a hard cutoff; scene stays fully playable at the cull distance.
  - **Risks/gates:** it's a streaming/presentation layer on top of the current renderer — reuse §7's "app still runs and looks identical" equivalence-gate discipline per phase (no pop-in + app unchanged); tune density/fog in `Config` before committing. Never touch physics/GL submission to add it.
  - **Dependency order:** do this *after* #1 (HDR/tonemap) and the LOD work feeding it; does NOT require multithreading (#10), Vulkan (#12), or Jolt (#11). Lowest-risk place to get the "vastness" feeling without a physics/GL rewrite.
