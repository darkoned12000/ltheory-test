# Limit Theory — Roadmap

The GL/GLSL 4.6 core ladder, the FMOD→miniaudio audio swap, and the library-currency pass are **complete**. The engine is fully 64-bit and runs the deferred+post rendering path on a modern core profile. What's left is feature investment, not correctness. Ordered roughly by expected impact / dependency order; each item is a self-contained project.

## Completed

## Rendering & graphics
3. **Bindless textures / texture arrays** for the deferred material path — fewer state changes with many materials.

6. **SPIR-V shader loading (4.6 feature)** — offline-compiled loads via `glShaderBinary`/`glSpecializeShader`; low priority (driver support varies; the custom `#include`/`#autovar` preprocessor must be replicated offline). Net win is startup-time only; the offline validator already catches compile errors.
14. **Graphics-options parity** — the debug panel currently exposes FOV, superSample, texture-filter, wireframe, backface culling, shadow radius/bias/scale, sun light/shadow, tonemap operator/EV + AE, bloom, sharpen, aberration, radialblur, vignette, grain, lighting (specular/ambient). Missing common knobs to add (data-driven behind `Config.gpu`/`Settings`): **motion blur**; **shadow-quality** (master on/off + PCF sample count + shadowmap resolution, on top of radius/bias/scale); **color grading** (saturation/contrast adjacent to EV + operator in `res/shader/include/tonemapping.glsl`); **runtime LOD distance-scale** (knob on the `VisibleLodMesh` distance² selector); micro-knobs **anisotropy stepping** (2/4/8/16× instead of a fixed 16×) and **mip bias**. GTAO (#2) and the landed distance haze (see #13) cover their slots; the remaining work here is the **motion blur**, **shadow-quality** (master on/off + PCF count + map resolution), and **color grading** micro-knobs.

## Platform & systems
11. **Jolt Physics** — the modern industry pick (SAP broadphase + multithreaded); only worth it if Bullet becomes a bottleneck — it's a full physics-integration rewrite. Keep Bullet 3 otherwise.

## Vastness & atmosphere systems
13. **Procedural streaming + LOD crossfade for endless sectors (atmosphere / vastness)** — the single biggest lever for the "never-ending, you are alone in a vast expanse" feeling. Render distance is what sells it: to feel endless you must keep generating/streaming content ahead of the ship and cull behind it, with no seam or pop-in. Design:
    - **Streaming/culling:** generate + stream new sectors/asteroid fields/nebulae into an expanding radius around the player (frustum + distance cull), recycle/despawn what falls behind — so the world reads as continuous rather than a fixed arena. The existing SDF `Gen/` pipeline + compute particles are reusable generators; extend them to be spawn-on-enter / kill-on-exit.
    - **LOD crossfade:** no hard LOD pop-in. Each entity renders at progressively lower-detail LODs and *crossfades* between them (alpha/scale blend) so detail degrades smoothly as it recedes — the eye never notices a discrete switch, which is what sells "forever." Asteroids are ideal: `max(15, scale*10)` health + cascading children already spawn at multiple scales.
    - **Fog + tonemapping:** the distance-haze half landed 2026-09-10 — `postfx.fog.*` aerial-perspective pass (`filter/fogw.glsl`) samples the nebula `envMap` along a per-pixel world ray, gates out the sky above `dist >= 950000`, and dissolves the horizon into haze pre-tonemap so it pairs with the HDR/tonemap cursor (#1). What remains for this item is the **streaming/culling** and **LOD crossfade** halves; the acceptance target "horizon fades into atmospheric haze, not a hard cutoff" is effectively delivered by the haze pass already.
    - **Feeling targets (acceptance criteria):** no pop-in or seam across long flights; asteroid/nebula density stays roughly constant as you move (feels endless); the horizon fades into atmospheric haze, not a hard cutoff; scene stays fully playable at the cull distance.
  - **Risks/gates:** it's a streaming/presentation layer on top of the current renderer — reuse §7's "app still runs and looks identical" equivalence-gate discipline per phase (no pop-in + app unchanged); tune density/fog in `Config` before committing. Never touch physics/GL submission to add it.
  - **Dependency order:** do this *after* the HDR/tonemap work (Completed) and the LOD work feeding it; does NOT require multithreading (#10), Vulkan (#12), or Jolt (#11). Lowest-risk place to get the "vastness" feeling without a physics/GL rewrite.
