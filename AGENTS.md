# Codebase Assessment: Limit Theory

## Project Overview
Limit Theory is an open-world space simulation game engine/game project, written primarily in C++ with Lua for high-level gameplay logic. Structured as a core library (`libphx`) and a main executable (`lt`).

## Technology Stack (Deep Dive)
Versions verified on this host 2026-08-28 (`ldd bin/libphx64r.so`, `pkg-config`, bundled headers in `libphx/ext/include/`). **Bundled headers now match the linked system runtime** (SDL/FreeType/LuaJIT/LZ4/stb all refreshed 2026-08-28).

### Core
- **Language: C++17** (bumped from C++11; `-std=c++17`, `-O3`, no exceptions, SSE4+ assumed, `Shared.cmake`). Possible upgrade: C++20/23 incrementally (concepts/designated initializers help engine code); zero ABI pressure since everything rebuilds from source.
- **Scripting: LuaJIT 2.1**, Lua 5.1 ABI — FFI bindings go through `ffi.cdef`/`ffi.load` (`libphx/script/ffi/*.lua`, generated by `libphx/tool/genffi.lua`); do not replace with standard Lua. Linked: **system OpenResty LuaJIT 2.1 rolling** (`2.1.0+openresty20251030`, GC64 x64); bundled headers refreshed 2026-08-28 to match (`2.1.1761786044`, `ext/include/luajit/`, `ext/bin/linux64/luajit` now 600k OpenResty build). Upgrade path: stay on the OpenResty rolling 2.1 (bugfixes land there); Lua 5.4/Luau are **not** viable — the whole engine surface is FFI/cdata based.
- **Build: CMake ≥3.16** via `configure.py` wrapper (`bootstrap.sh` installs deps). The offline GLSL validator resolves its interpreter via `_validator_py()`: prefers the project venv `.venv-tools/bin/python`, then `$PHX_VALIDATOR_PY`, then `python3`. CMake floor is fine; no urgency to chase CMake 4.x.
- **Bitness: 64-bit x86-64 everywhere** (`bin/lt64r`, `bin/libphx64r.so`, ext libs under `libphx/ext/lib/linux64`). No 32-bit artifacts in the Linux build.

### Graphics
- **OpenGL 4.6 core + GLSL 460 core** — the whole rendering path (deferred + post chain). Engine prepends `#version 460 core` (`Shader.cpp:27`); `.glsl` files must not carry their own. One global VAO for process lifetime (`OpenGL_Init`). See "Load-bearing architecture" below for the invariants that matter.
- **GLEW 2.3.1 (system)** — GL loader. Note: AGENTS previously said 2.2.0; `ldd` shows `libGLEW.so.2.3` (2.3.1) is what actually links (2.2.0 also installed). Candidate for removal long-term: GL 4.6 core could use a leaner loader (glad/EGL directly), but GLEW is working — low value to churn.

### Runtime libraries (linked into libphx)
- **SDL3 3.4.14 (system runtime)** — windowing, GL context (`SDL_GL_SetAttribute` core profile in `Engine.cpp`), input (keyboard/mouse/gamepad/joystick via engine wrappers + `gamecontrollerdb_205.txt`), timing. Migrated from SDL2 2.32.70 (2026-09-03, see `SDL_Migration.md`): `SDL_GameController*`→`SDL_Gamepad*`, `SDL_EVENT_*` enum renames, `SDL_CreateWindow(title,w,h,flags)`, `SDL_GL_DestroyContext`, `SDL_GetJoysticks()` enumeration, `SDL_GUIDToString`, `SDL_Init`/`SDL_InitSubSystem` bool returns, `SDL_GetNumLogicalCPUCores`. Bundled SDL2 headers (`ext/include/sdl/`) deleted — the engine includes system `<SDL3/SDL.h>` via the `libphx/include/SDL.h` shim. Audio stayed on miniaudio throughout (SDL audio never used).
- **Bullet Physics 3.24 (system)** — rigid bodies, collision shapes (`CollisionShape.cpp`), swept asteroid field; engine compiles against system headers (`/usr/include/bullet`, ABI-matched; stale bundled 2.87 headers removed). Upstream Bullet is effectively frozen (3.25, 2023). Possible upgrade: **Jolt Physics** (the modern industry pick, SAP broadphase + multithreaded) — but it's a full physics-integration rewrite; only worth it if physics becomes a bottleneck. Keep Bullet 3.
- **Audio: miniaudio 0.11.25 (vendored single header, `libphx/ext/include/miniaudio/`)** — **swapped in 2026-08-28, replacing FMOD 1.10.01**. `Audio.cpp`/`Sound.cpp`/`SoundDesc.cpp` were rewritten behind the unchanged `Audio.h`/`Sound.h` C API; Lua FFI (`ffi/Audio.lua`/`Sound.lua`) untouched. `MINIAUDIO_IMPLEMENTATION` lives only in `Audio.cpp`; `SoundDef.h` hides `ma_sound`/`ma_resource_manager_data_source` behind forward-declared pointers. Backends dlopen at runtime (PulseAudio/ALSA/JACK on Linux). Mapping: desc = RM data source (`DECODE`→f32, `ASYNC`→job-thread loads w/ notification callback), voice = `ma_sound_init_from_file` (RM dedupes decoded data by path; clones get independent cursors), doppler/rolloff/min-distance applied per-voice at creation, finish-detection polled via `ma_sound_at_end` in `Audio_Update`. 3D tuning (measured 2026-08-28 with a null-device RMS probe): miniaudio inverse rolloff with minDist=10/rolloff=2 gives only ~36% gain at 12 units and ~10% at 30 — near-silence at chase-cam distances. `Sound_Set3DMinMaxDistance` (also exposed via FFI) fixes per-sound loudness. **All gameplay SFX are data-driven via `Config.audio.sfx`** (`Config.App.lua`): `{ sound = asset, volume = linear gain, minDist = full-volume radius }` keyed by logical effect name (blaster/explosion/engine; add afterburner, shieldHit, hullHit, UI blips there) — override entries in `Config.Local.lua` to audition changes without touching gameplay code. Music: `Config.audio.music/musicVolume` (2D, unattenuated), `M` key toggles playback. Engine mixer is forced to stereo (native channel counts pan dead-ahead sounds into center/rear channels stereo speakers never play) with 40 ms periods + 100 ms gain smoothing to prevent underrun crackle and zipper noise; per-frame `setPitch` must be throttled (resampler crackle) — see `ThrustController`. **Known limitation: miniaudio's embedded stb_vorbis rejects some valid Vorbis streams** (e.g. upstream `Imperial_March.ogx`) even via the memory path — that file was converted to `Imperial_March.wav` with ffmpeg; prefer WAV/MP3 assets.
- **FreeType (headers + runtime both 2.14.3 as of 2026-08-28)** — font rasterization (`Font.cpp`, TTFs in `res/font`). Bundled headers were refreshed from the system dev package (`/usr/include/freetype2` → `ext/include/`), fixing the old 2.8.0-vs-2.14.3 skew.
- **LZ4 1.10.0 (system + bundled header 2026-08-28)** — block compression for `Bytes` (serialized/gen data); `ext/include/lz4/lz4.h` refreshed to 1.10.0, `ext/lib/linux64/liblz4.*` (1.7.5) deleted — `libphx/CMakeLists.txt:44` links system `liblz4.so.1`.
- **stb_image v2.30 / stb_image_write v1.16 (vendored, current as of 2026-08-28, `libphx/ext/include/stb/`)** — `Tex2D_Load.cpp`/`Tex2D_Save.cpp` texture I/O, with magenta-fallback resilience. Verified byte-identical to upstream `https://github.com/nothings/stb` master (`sha256 594c2fe...` / `cbd5f0a...`, drop-in single-header via `STB_IMAGE_IMPLEMENTATION` / `STB_IMAGE_WRITE_IMPLEMENTATION`). Legacy `stb.h v2.24` was unused (zero `#include "stb/stb.h"` consumers) and has been removed — upstream moved it to `deprecated/stb.h` (now v2.37).
- **ALSA (Linux) / WINMM (Windows)** — raw MIDI input (`Midi.cpp`, `MidiDevice.lua` FFI). Implemented but unused by any app; small, harmless, keep for future music-tooling.

### Engine-internal subsystems (no external dep)
- **HmGui** — retained-mode GUI actually used by the game (`script/Game/GUI/`). **ImGui** (engine-internal immediate mode, *not* dear imgui) — test apps only (`TestImGui.lua`, `RenderTest.lua`). Two GUI systems coexist; consolidation is optional cleanup, HmGui is the live one.
- **Resource system** (`Resource.cpp`), **SDF `Gen/` pipeline** (procedural mesh/planet generation), **compute particles**, **MemPool/MemStack** allocators, **Profiler** (`Profiler.cpp`), **StrMap/HashMap/Octree/KDTree/BSP** spatial structures.
- **Lua scheduler** (`LuaScheduler.cpp`) — coroutine-driven app update loop bridging C++ main loop → Lua apps (`script/App/*.lua`).

### Audio backend — FMOD → miniaudio (SWAPPED, 2026-08-28)
Decision record from the evaluation: candidates were miniaudio (chosen — single-header C99, public-domain/MIT, zero licensing risk vs FMOD's proprietary license, `ma_engine` covers the whole existing API incl. async RM loads and MP3/WAV/OGG decode), SDL2_mixer 2.8.2 (fallback — distance+angle positional only), OpenAL Soft (only if HRTF becomes a priority; LGPL runtime dep), SoLoud (unmaintained), and SFML audio (rejected — it wraps miniaudio anyway while dragging in SFML's windowing/system layer). The swap is done; `FMODError.h`, `ext/include/fmod/`, and all fmod libs/links are deleted.

**Asset note:** every binary in `res/` (audio, textures, meshes) is a **Git LFS pointer** in the upstream repo — a plain clone without git-lfs leaves 129-133 byte ASCII stubs. The real 280 MB was fetched from upstream's public LFS media endpoint (`media.githubusercontent.com/media/JoshParnell/ltheory/master/...`) and sha256-verified against the pointer OIDs (2026-08-28). That also resolved the late "corrupted textures" scare — they were never corrupt. If new clones show placeholder-size files, fetch LFS objects the same way or `git lfs pull`.

## Current State — GL 4.6 / GLSL 460 CORE (ladder complete)
Context `Engine_Init(4,6)` → GL 4.6 core (`src/Main.cpp:15`, `libphx/src/Engine.cpp`); shaders compiled at `#version 460 core` (`libphx/src/Shader.cpp:27`); GLEW prints a `[GL] ... glew-4.6 yes/no` flag on boot. Zero legacy tokens across shaders AND C++.

### Load-bearing architecture (read before touching rendering code)
1. **Global VAO** (`OpenGL_Init`) — core profile has no default VAO; one is created after `glewInit()` and bound forever. All draw attrib state lands in it.
2. **No program-0 draws**: Mesa core rasterizes nothing silently when no program is bound. **Every draw must run under an explicitly started program.** `Renderer.lua`'s `present/presentAll/startPostEffects-downsample` wrap their quads in `Cache.Shader('ui','filter/identity')`.
3. **Eager autovar trap**: `#autovar` uniforms upload once, at `Shader_Start`, not per-draw. A pass that starts its shader before pushing its render-target viewport bakes in window matrices. Start the shader inside the first RT push. Matrix-free passes (`identity.glsl`) are immune.
4. **Flat immediate batch** (`Draw.cpp`): `Draw_Rect/Line/Tri` primitives with an unchanged (mode, color, textured) signature accumulate into a single draw and flush on run-key change, active-program change, texture blit, any `RenderState`/`RenderTarget` push/pop, `Shader_Start`, `ShaderVar_Push/Pop`, `Window_EndDraw`, line/point-size change, or VBO overflow (4096 verts). Draws issued while an explicit program is active (postfx/wrapper shaders) bypass the batch via the legacy direct path — never move a per-primitive program change into a batched run, and flush `Draw_FlushPending` before any of those in Lua. Covered by headless validator `tools/validate_immdraw.lua` (runs in `configure.py test`).

### Offline validator (safety net for `.glsl` edits)
`./configure.py test` → `tools/validate_glsl.py`: compiles+links every vs/fs headlessly via moderngl/EGL at the engine's GLSL level, auto-parsed from `Shader.cpp`. EGL validates at `<NNN> core` (stricter than runtime). **Always run before any shader edit.** A typo now fails at configure time. The validator's interpreter comes from `.venv-tools` (see Tech Stack), so configure as `./configure.py` (or `env PHX_VALIDATOR_PY=... ./configure.py`).

## Gameplay Systems (Lua) — Asteroids, Damage, Targeting
Live in `script/Game/`. The event model: every damageable entity calls `Entity:addHealth(max, rate)` (`rate=0` = no regen); hurt via `entity:damage(amount, source)`; health 0 fires `Event.Destroyed`; listen with `entity:register(Event.Destroyed, handler)`.
- **Asteroids** build a procedurally generated mesh + rigid body + visible LOD mesh (cached per seed). Health = `max(15, scale*10)`. Death spawns 2–4 smaller children (cascading) + an explosion burst. `System:sweepDestroyed()` (each update) removes dead/`deleted` children and pulls their bodies out of physics — without it you could still crash into a "destroyed" rock.
- **Ramming** (`System:handleRamming`) maps rigid-body collisions → entities, deals symmetric damage above a relative-speed threshold.
- **Targeting/HUD**: `drawTargets` locks the nearest entity within 128px of screen center; `T`/`G` lock/clear; `drawLock` clears on death and draws a health bar over the target.
- Spawn a field: `self.system:spawnAsteroidField(2000, 20)`. Manual: build an `Entities.Asteroid(seed, scale)`, `setPos(Vec3f(...))`, then `self.system:addChild(a)`.

## Post-4.6 Hardening (all done)
- **Validator restored**: `moderngl` in `.venv-tools`; `configure.py test` runs headlessly (llvmpipe/EGL). Fails fast on any shader typo.
- **Graceful runtime shader failure** (`74f717a`): C++ non-abort + cached-good program fallback + in-game overlay naming the bad pass. A broken shader degrades instead of crashing.
- **GPU-quality settings panel** (`Config.gpu`, Renderer seeds bloom/sharpen from it at startup) — weak hardware drops expensive post-passes instead of shipping broken; visually testable via the planet's atmosphere rim glow.
- **Planet spawn**: `System:spawnPlanet()` returns its handle; app pushes the ship clear of the surface if too close (bearing preserved).
- **Point-light shadow maps**: per-light Depth32F ortho shadow maps + PCF test in `point.glsl`, rendered/fed from `GameView.lua:renderShadows` (commit `df8c1a8`); tuning via `render.shadow.{bias,scale,radius}`.
- **Explicit uniform locations**: `deferred.glsl` `fragData0/1/2` carry `layout(location=0/1/2)`, matching the effect shaders' `layout(location=0)` convention.

## Gameplay / Build Notes Worth Knowing
- **Bullet**: engine compiles against **system Bullet 3** headers/libs (ABI-matched); stale bundled 2.87 headers (`bullet_old_2.87/`, 221 files) removed.
- **Texture resilience**: missing images log a warning + use a 1x1 magenta fallback instead of aborting (was `Fatal()`).
- **Run:** `./run.sh LTheory` from the repo root; no `LD_LIBRARY_PATH` needed (`$ORIGIN` RUNPATH + absolute-path FFI loader).
- **Wayland**: `run.sh` drives SDL3 via the native Wayland backend (when `WAYLAND_DISPLAY` is set) so the window is a first-class Hyprland client — decorated, closable, and sized/clamped by the compositor instead of a throwaway X server. A stale `DISPLAY` is unset to avoid SDL falling back to an unreachable X11 address.
- **Window setup / quit**: `Config.window.{width,height,fullscreen,quitKey}` in `script/Config.App.lua` (override in `Config.Local.lua`) drives launch size + fullscreen + a quit key. The quit key matters on Wayland tilers whose windows have no title-bar close button; the base `Application` reads it in `Application.lua`.
